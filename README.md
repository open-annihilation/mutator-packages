# Mutator packages

Sources of the mutator packages built for Open Annihilation: the curated translations of the TA: Mutation corpus and the examples. Private until the maintainer decides how each is published.

Each family is a folder of package sources. [Originals and builds](#originals-and-builds) says what those folders hold, where the TA: Mutation originals live, and how a build is made from them.

## Originals and builds

This repository holds only what we write: manifests, Lua, rules, allowed differences, recorded reports, notes and scripts. It never holds an original archive or any file taken out of one. No `.ccx`, `.tam` or original `.sm`, no model, script, GAF, unit, weapon or GUI file, and no faithful import. `originals/` and `build/` are gitignored. `originals/` is the originals; `build/` is made from them.

`originals.tsv` lists the nine archives by their keys in `s3://coreprime-downloads-originals`. The bucket is private. The three corpus archives, set `ta-mutation`, have no public URL (the `url` column is `-`):

- `tools/ta-mutation/Mutators.zip`
- `tools/ta-mutation/S-Mutators.zip`
- `tools/ta-mutation/H-Mutators.zip`

The maintainer fetches those with `aws s3 cp --profile oa-publisher` when there is no local copy. The same bytes are on this machine in `~/Downloads/legacy-mods/ta-mutators/` (read only). The six igi-server archives, set `igi-server`, are public. Each URL is `https://files.igi-server.link/` plus the server path (`MAC's mutators.zip`, `finitemetalta_mutator.zip`, `finitemetalta_cs_mutator.zip`, `tam-directionalfactoriesv2.zip`, `DTAM.ZIP`, `TA Stuff/New/immerpack10.zip`). The same bytes are in `~/Downloads/legacy-mods/ta-mutators-igi/` at those server paths (read only). The private regression suite keeps test copies under `fixtures/mutators/originals/` and `fixtures/mutators/originals-igi/`, and its cases pass those folders as `--from` and `--from-igi`. This repository holds none of them.

The igi server needs no credentials. It refuses Python's default user agent, so a download sends `curl/8.7.1`, and it serves no loose files outside the zip paths. The request percent-encodes the server path (`urllib.parse.quote(path, safe="/")`), which encodes the space and the apostrophe in `MAC's mutators.zip`.

`tools/fetch-originals` reads `originals.tsv` and fills `originals/`. `--set ta-mutation` and `--set igi-server` (repeatable) limit the run; the default is every row. A zip already at `originals/zips/` with the listed size and SHA-256 is kept. Otherwise the local copy is checked and copied. Without a local copy, an igi row is downloaded from `--igi-url-base` (default `https://files.igi-server.link/`) and a corpus row is the maintainer's `aws` command above. `--local-only` does not download: a missing file exits 1 and names the URL or that `aws` command. A size or SHA-256 that differs, or a failed download, deletes the partial file and exits 1. A download follows a redirect only when it keeps the URL's scheme, host and port, and reads no more than the row's size (`MAX_DOWNLOAD_BYTES`, 8 MiB, caps every row). A refused redirect, an HTTP error, a timeout, or a body that is too short or too long prints `originals: <name>: download failed: <url>: <reason>`. The tool then unpacks each zip of the run, replacing the tree: the corpus into `originals/Mutators/`, `originals/S-Mutators/` and `originals/H-Mutators/` (the S and H trees keep each mutator as its own zip), and the igi archives into `originals/igi-server/<server path without .zip>/`. Entry names without the UTF-8 flag are read as Windows-1252 and stored as Unicode NFD. An absolute entry, or one that contains `..`, is refused. Nested zips are left as zips.

`tools/build-packages --tool OA_TOOL` builds families into `build/`. `--originals` and `--out` override the two directories. With no family name, every top-level folder that holds `_imports.tsv` or `_verify/` is built. Before building, every `source` those families name must exist under `originals/`; the first missing one exits 1 and says to run `tools/fetch-originals` (with `--set igi-server` when the source is under `igi-server/`). `--out` may not be empty, the repository, a folder above it, or a folder inside `--originals`. Inside the repository it must be `build/` or a folder below it, so a build never lands in a family's sources or `tools/`. These are usage errors (exit 2), reported before anything is removed. The tool marks each family folder it builds with a `.build-packages` file and replaces only a marked folder; any other folder at `<out>/<family>` is refused the same way. A family is built in a temporary folder beside `<out>/<family>` and moved into place only when the whole family built. A failed family leaves no `<out>/<family>`, not even an earlier build. Each family's build holds:

- `_imports/<import id>/`, the faithful import, exactly as `oa-tool mutator import` writes it. One fresh scratch folder per row, removed at the end. The tool's output is `build/<family>/_logs/import-<import>.txt`.
- `<id>/`, each curated package: the source folder without `from-originals.tsv`, plus the files that list names. Each file's SHA-256 is checked. A source folder that already holds `files/` fails the build.
- `_verify/`, a copy of the family's.

Every pack, check and diff runs in `build/<family>/`, so paths such as `./quick-build` and `_imports/<id>` are relative to that directory. The tool writes nothing outside `--out` and its scratch folders. Exit 2 when `--tool` is missing.

`tests/` holds small checks of the two tools' refusals: the `--out` checks, a repeated import, a failed family, and the download bounds. They use made-up files, a fake `oa-tool` and a server on 127.0.0.1, never the originals or the network. Run them from the repository's top level with `python3 -I -m unittest discover -s tests -t .`.

### Family layout

A family folder is owned by that family's translation. `<id>/` is one curated package's source: `oamut.yaml`, `mutator.lua`, and where needed `rules/` holding `.sm` files written for the package. Where the package needs bytes from the originals, `from-originals.tsv` names them. The source never has a `files/` folder. There is no `icon.png`: the Library and Core Prime draw the first tag's icon, so the first tag is chosen for that.

`_imports.tsv` is tab-separated. The header is `import`, `source`, and a family whose originals share a title adds a third column `id`. `import` is the id `oa-tool mutator import` makes from the title (the folder name it prints). `source` is the `.tam` (its companions beside it) or the zip, under `originals/`, for example `Mutators/{}QuickBuild2x.tam`, `S-Mutators/FastStumpy_mutator.zip` or `igi-server/MAC's mutators/{}MAC Bio-Armor.tam`. One row per original, in the family's order. Each `import` appears once: a repeated one is refused, naming both lines, before anything is built. On the optional `id` column, a row that needs `--id` writes that id (the same as `import`); the other rows write `-`.

`from-originals.tsv` is tab-separated with the header `path`, `source`, `entry`, `sha256`. `path` is the file's place in the assembled package (`files/objects3d/KROGCOM.3do`). `source` is the original under `originals/` (`Mutators/}{KroggyComm11.ccx`). `entry` is the entry inside that archive, as the archive names it, or `-` when `source` is itself the file. `sha256` is the file's SHA-256. The family's README lists the same files.

`_verify/comparisons.tsv` is tab-separated with the header `row`, `curated`, `imports`, `allowed`. A family whose rows need a mod or a map adds `mod` and `map`, in that order, and writes `-` where a row needs neither. `curated` is one or more specs, separated by spaces and applied in that order, each a package folder in `--mutator` form relative to `build/<family>/` (`./quick-build`, `./quick-build:factor=8`). A row named as a package, with no options, has `./<package>` as its `curated` spec. `imports` is the faithful imports it must match, space-separated (`_imports/<id>`), or `-` when no import is comparable. `allowed` is a file name in `_verify/` or `-`. In a comparison the curated package is the left side and the imports are the right side. `mod` names an archived OAMOD package folder under `~/go/src/github.com/coreprime-archive/mod-packages/` (`utasp-v5.0`), passed as `--mod-dir`. `map` is a map name passed as `--map` (`Acid Pools`). Families without those columns keep four columns.

`_verify/<row>.allowed` holds only the differences that family's notes document, each pattern under a `#` reason line. A pattern must match at least one difference. `_verify/<row>.3.1c.txt` is byte for byte what `oa-tool mutator diff --game-dir "$OA_GAME_DIR"` prints with one `--mutator` per spec of `curated` (and the row's `--map`), run in `build/<family>/`. A row with a mod records `_verify/<row>.<mod>.txt` instead, from the same command with `--mod-dir`. `README.md` in the family folder is the family's record.

Manifest keys, in the forms the engine's `src/formats/oamut/README.md` gives: `oamut: 1`; `id` as the folder name; `name` in plain English; `version: "1"`; `author` the original author or authors as the corpus credits them (`Unknown` when the files credit no one, and the description then says where it shipped); `description` in plain English (the `.tam` text rewritten, `#` breaks dropped), ending with a sentence on what the curated version fixes, and naming the originals it replaces with their authors; `tags`, one to four of `statistics`, `economy`, `commanders`, `new-units`, `disable`, `gameplay`, `ai`, `maps`; `works-with` as named (here `["*"]` for every package); `requires: { engine: ">= 0.8.5" }`; `layers`, exactly the layers the package uses; `options` where the package has any. `legacy` is one record (`name`, `prefix`, `compatibility`, `files`) for every original the package replaces, in that order, each copied unchanged from that original's faithful import. No `strings` (English only for now) and no licence lines.

Lua rules use the engine's forms (`src/data/mutators/README.md`, Rules in Lua): `where { needs }:change { changes }`, `all()` for every record, `named("X")` for one unit, `on(folder, extension)` for other targets (`on("weapons", "tdf")`, `on("features/corpses", "tdf")`, `on("gamedata", "sidedata.tdf")`). Needs are `range`, `is`, `has`, `absent` and `not_`. Changes are `set`, `scale` (a clamp is `scale(k, lo, hi)`), `lock` (the originals' `^`), `remove`, `append`, and the key `"<AllDepth2>"` for every damage value. One `.sm` block and its Lua spelling give the same records. Two changes to one field in one block are two blocks. Where a block has no Lua form, keep it as a `.sm` file of the package's own in `rules/` (`sm "rules/<name>.sm"`), holding that block written out for the package, never an original `.sm` copied whole, and say so in the family's README. Hooks only where the package's notes name one. Select by properties; select by unit name only where the original changes named units, and say so in the description.
